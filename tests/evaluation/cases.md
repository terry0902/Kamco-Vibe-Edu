# 소요 시간 측정 안내

조치 방법을 찾는 시간을 앱 사용 전후로 비교한다. 목표는 평균 5분 이내이고, 사람이 직접 측정한다.

- **시간 기준:** 증상을 확인한 때부터 적용할 조치 방법을 확인할 때까지
- **사용 전:** 샘플 매뉴얼과 관련 없는 공개 문서를 섞은 임시 폴더에서 직접 찾는다. 파일 이름으로 내용을 알 수 없게 바꾸면 실제 상황에 더 가깝다.
- **사용 후:** 같은 사례를 앱으로 찾는다.
- **측정자:** 앞선 측정의 기억이 영향을 주지 않도록 가능하면 사전과 사후의 측정자를 나눈다. 혼자 측정하면 그 사실을 결과에 적는다.
- **한계:** 임시 폴더는 실제 공유 폴더보다 작아서 현재 추정치 30분과 그대로 비교할 수 없다. 이 차이를 결과와 함께 적는다.
- **주의:** 실제 사내 정보를 쓰지 않는다.

## 장애 사례

각 사례의 "상황"을 측정자에게 그대로 보여 주고, 앱에는 측정자가 직접 입력한다.

| 번호 | 상황 | 찾아야 할 내용 |
|---|---|---|
| 1 | 로그 수집 서버에서 파일 쓰기가 실패하고 `No space left on device`가 나온다. | 용량 확인, 용량을 많이 쓰는 폴더 찾기, 지워도 되는 대상 정리 |
| 2 | 야간 배치 서버의 프로세스가 이유 없이 사라졌고, 시스템 로그에 `Out of memory: Killed process`가 있다. | 종료된 프로세스 확인, 메모리 확인, 서비스 재시작 |
| 3 | 웹 서비스가 `502 Bad Gateway`를 돌려준다. | nginx와 백엔드 상태 확인, 오류 로그 확인, 백엔드 재시작 |
| 4 | RAID 장치에 디스크 장애 경보가 왔고 `/proc/mdstat`에 `[U_]`가 보인다. | 장애 디스크 확인, RAID에서 빼기, 교체 후 추가 |
| 5 | 파드가 노드에 배치되었지만 이미지를 받지 못해 Waiting 상태다. | 파드 이벤트 확인, 이미지 이름과 레지스트리 확인 |
